# Практическая работа № 7 — уровень B

**Тема:** IPC: FIFO, Unix-сокеты, общая память и Pipe.

## Автоматическая демонстрация

```bash
bash run.sh
```

`run.sh` запускает два сервера, отправляет запросы, останавливает серверы и выполняет замер на **10 миллионах `uint32`** (40 MiB). Требуются Linux, Python 3.11+, свободные примерно 40 MiB в `/dev/shm` (у Docker по умолчанию часто 64 MiB).

## FIFO в двух терминалах

Терминал 1:

```bash
python3 fifo_server.py --dir /tmp/pr07-ipc
```

Терминал 2:

```bash
python3 fifo_client.py '2*(4+3)' --dir /tmp/pr07-ipc
python3 fifo_client.py '10 / 2' --dir /tmp/pr07-ipc
```

Для оценки времени короткого сообщения используется `measure_latency.py` (10 запусков клиента, медиана). Сервер принимает один запрос за другим через `requests.fifo`. Для каждого клиента создан второй FIFO `reply.fifo` во временном закрытом каталоге, который клиент удаляет после ответа.

## Unix-сокеты в двух терминалах

Терминал 1:

```bash
python3 unix_server.py
```

Терминал 2:

```bash
python3 unix_client.py '2+5'
python3 unix_client.py '9*9'
```

Сервер использует `socket.AF_UNIX` через `socketserver.UnixStreamServer` + `ForkingMixIn`: каждый клиент обрабатывается в отдельном дочернем процессе (в ответе выводится PID). Можно запустить несколько клиентов параллельно.

## SharedMemory против Pipe

```bash
python3 compare_memory.py --count 10000000
```

Передаётся массив из 10 миллионов 32-битных чисел. В обоих случаях принимающая сторона считает сумму и возвращает её для проверки. `Pipe` переносит все байты; `SharedMemory` передаёт имя общего сегмента, а данные читает без отправки через канал. Измерение включает старт процесса и проверку суммы, но **не** подготовку массива. Поэтому время включает и вычислительные накладные расходы — это не чистая пропускная способность памяти. Данные очищаются через `unlink()`.

## Сравнение

| Механизм | Синхронизация в прикладном коде | Размер | Замер |
|---|---|---|---|
| FIFO | Протокол запрос/ответ | Короткое выражение | Медиана round-trip из `run.sh` |
| Unix-сокет | Сессия клиент/сервер | Короткое выражение | Медиана round-trip из `run.sh` |
| Pipe | Обмен/чтение | ~40 MiB | Печатается после запуска |
| SharedMemory | Требуется сигнал готовности | ~40 MiB | Печатается после запуска |

В демонстрационном тесте на Linux-контейнере для 10 млн чисел измерено около 1.17 с на Pipe и 0.73 с на SharedMemory (включая запуск и сумму). При вашем запуске значения будут другими. Для FIFO и сокетов выводится медиана времени короткого запроса (включает запуск клиента), поэтому напрямую сравнивать четыре числа нельзя.

Общая память часто быстрее для больших сообщений, поскольку избегает повторной пересылки через ядро, но программист обязан отдельно согласовывать момент чтения/записи. Для безопасности калькулятор использует AST, не `eval`.
